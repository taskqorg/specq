# Independent product connections

Accepted rules for connecting independently installed products. Consumer contracts own protocols, endpoints, schemas, credentials, bounds and release evidence.

- One supported command starts connection; one authenticated browser approval names destination, account, scope and installation. Headless hosts use the same approval elsewhere. No copied secrets, file editing, extra service or inbound host port.
- Reuse installed identity, updater, service loop and bounded delivery. A shared library owns only repeated connection mechanics; each product owns its state and allowlisted projection. Products remain useful alone and through outages.
- Observation grants cannot authorize commands. Bind ownership server-side; isolate accounts and workspaces on every read/write path. Names and IP addresses do not prove identity. Never inherit another product's access.
- Enrollment is idempotent. Activation is atomic; queued data retains its approved destination. Cancellation, lost replies, crashes, disconnect, offline revocation, reconnection and reinstall have explicit outcomes.
- Connected means a real snapshot committed durably and read back through the dashboard's projection. Acceptance, projection, export and component health are different facts. Missing history stays missing.
- Acknowledge after durable commit; retries keep stable IDs. Bound storage, requests, retries and retention. Report gaps and backpressure; no silent loss after acknowledgement. Revocation survives restart and is checked on every authenticated request.
- Keep credentials protected and diagnostics secret-free. Credential lifetime and rotation follow the security baseline or an explicit owner-accepted, narrowly scoped consumer exception.
- Preserve standalone behavior, existing work and capture consent during migration. Source observation time drives freshness; delivery time never refreshes an old measurement.
- Qualify the whole installed path, including identity guard, desktop/headless consent, outages, saturation, restore, revoke and cross-account denial. Shared code needs at least two independent consumer fixtures. Mergeable implementation steps are not partial product releases.
