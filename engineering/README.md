# Engineering rules

Reusable engineering rules. Projects link to the applicable rule and define their own implementation details.

- [Working principles](principles.md): shared-rule ownership and project boundaries.
- [Spec first](spec-first.md): canonical decisions, project boundaries, keeping the owner's request and the improvement route.
- [Project contracts](contracts.md): contract shape, writing rules, size budget, overflow path and lint.
- [Ponytail](ponytail.md): the smallest change that fully solves the task.
- [Agent workflow](agent-workflow.md): ownership, decided rules, queue flow, work cycle, approval boundaries and completion.
- [Task planning](task-planning.md): task preparation, experiment tasks, PM intake and runtime preference.
- [Review and learning](review.md): review of a frozen result and learning from friction.
- [Rule delivery](rule-delivery.md): attempt context, injected core and agent integration.
- [Use cases](use-cases.md): scenario structure, overlap and requirement coverage.
- [Verification](verification.md): evidence boundaries, unknown health and scoped remediation.
- [Behavioral models](behavioral-models.md): state-driven systems and optional formal checks.
- [Testing](testing.md): test decisions, risk coverage, run selection, time budgets and disagreements.
- [Data and storage](data.md): store, durability, atomic files, bounds and crash checks.
- [Performance and capacity](performance.md): observe-not-gate rule, load tasks, order of work and resource budgets.
- [Built-in profiling](profiling.md): operation counters, agent work stages, system operations, traces, bounded store, analysis export and profile reports.
- [Release, update, service](release-contract.md): verifiable releases, safe updates, self-maintenance, host requirements and service ownership.
- [Permission authority](permission-authority.md): trust boundaries for agent access.
- [Independent product connections](product-connections.md): consent, isolation, delivery, recovery and end-to-end evidence.
- [Security baseline](security.md): secrets, [one durable GitHub token per host](security.md#one-durable-github-token-per-host) and untrusted agent input.
- [Repository and release security](repository-security.md): repository protection, workflows, dependencies, releases and the review routine.
